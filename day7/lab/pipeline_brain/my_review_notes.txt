     - Progress checkpoints (after filter, after dedup, etc.)
     - Final record count written to output
     - Any errors with full exception context

SPECIFIC LINES CHANGED:

  - Lines 42-101: transform_silver() wrapped in try/except

    * Tracks record loss at each stage

  - Lines 108-116: build_merchant_performance() wrapped in try/except

FIX 2: HARDCODED PATHS (FAIL → PASS)
═══════════════════════════════════════════════════════════════════════════════

ISSUE:
  Original pipeline had hardcoded S3 paths scattered throughout:
    input_path = "s3://sigma-datatech/bronze/transactions.csv"
    merchants_path = "s3://sigma-datatech/bronze/merchants.csv"
    bronze_path = "s3://sigma-datatech/silver/transactions"
    silver_path = "s3://sigma-datatech/silver/transactions"

  Risk: Cannot run on different environments (dev, staging, prod) without
  editing code. Breaking bad practice that prevents reuse.

WHAT WAS CHANGED:
  1. Made paths function parameters instead of hardcoded strings:
     def main(input_path, merchants_path, bronze_path,
              silver_path, gold_output_dir, run_date, run_id):

  2. Moved hardcodes to constants at bottom of script:
     INPUT_PATH = "s3://sigma-datatech/bronze/transactions.csv"
     MERCHANTS_PATH = "s3://sigma-datatech/bronze/merchants.csv"
     BRONZE_PATH = "s3://sigma-datatech/layer/bronze"
     SILVER_PATH = "s3://sigma-datatech/layer/silver"
     GOLD_OUTPUT_DIR = "s3://sigma-datatech/layer/gold"

  3. All function calls now pass these as parameters

SPECIFIC LINES CHANGED:
  - Line 104: main() signature now accepts all paths as parameters
  - Lines 297-301: New configuration section with constants
  - Lines 303-311: main() called with parameterized values

WHY THIS MATTERS:
  - Multi-environment support: One code base, different configs for dev/prod
  - Testing friendly: Can inject test paths without modifying source
  - Ansible/Airflow integration: Can pass paths from environment variables
  - Code review practice: Separates configuration from logic
